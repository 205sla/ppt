사람의 음성, AI에게 제공하는 게임 상태, 계층적 판단, 실제 이동과 발판 유지가 같은 장면에서 연결되는 구조다. 데이터와 움직임은 설명을 위한 예시이며 API와 게임을 실제 실행한 화면은 아니다.

GPT-Live의 기본 오디오는 WebRTC 미디어 트랙을 사용한다. 앱은 같은 세션의 데이터 이벤트와 서버 sideband로 전사·위임·문맥을 관리한다. client 위임의 생성 이벤트에는 지시문이 없으므로 전사와 기존 작업을 조정기에서 연결한다. 전사 delta의 누적이나 침묵만으로 지시를 확정하지 않고, 수정·부정·대상과 현재 상태를 확인한 뒤 실행한다.

게임 JSON, task_epoch, operation_id, hold_blue는 우리 앱의 예시 명세다. 모델은 후보를 제안하고 조정기가 현재 작업·대상·전제조건을 검사한다. Accepted는 명령 접수, Moving은 이동 중, Holding은 실제 발판 접촉 유지다. Holding 상태에서도 플레이어 통과 확인 전에는 작업이 끝나지 않는다.

‘이동 중 계획도 요청’을 켜면 역할 교대라는 추가 목표를 별도로 검토하는 경우를 보여준다. 느린 계획을 기다리는 동안 현재 유효한 이동과 유지 행동을 계속한다. 모델의 실행 시간이나 병렬 GPU 추론 성능을 측정한 예시는 아니다. 계획의 결과는 검증 후 후속 행동에 반영한다.

결과 회신의 session.commentary.append는 최대 500토큰의 문자열 content와 실제 받은 delegation_id를 사용한다. item_demo는 설명용 ID다. 회신 접수와 실제 음성 재생은 별개이며 마지막 단계는 결과를 음성으로 안내하는 전체 과정의 예시다.

근거: GPT-Live WebRTC, 세션·전사·문맥, client delegation, HLA. 15장 상세 설명의 1·2·7페이지를 통합했다.
