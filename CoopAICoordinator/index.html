AI는 2개. 조정기·기억·실행기는 일반 코드.

약 40초. 프로젝트는 사람이 AI 동료와 음성으로 협동하는 Unreal 3D 퍼즐입니다. 저는 대화와 게임 행동 사이를 연결하는 조정기를 맡았습니다. AI는 대화 AI 하나와 행동 AI 하나이며 조정기를 별도 AI로 추가하지 않았습니다. 이번 주에는 공통 흐름과 모의 왕복을 구현했고, 실제 팀원 퍼즐과 모델을 붙이는 작업은 다음 단계입니다.

기준: 2026-10-02 사용자 제공 흐름도·주간 회의 내용, 2026-09-30 구현 기록, 2026-10-01 main 반영 및 재검증 기록. 코드 기준 커밋: 869708ee3902a51966cc3721003b9a257545cd67.

01 / 전체 설계

조정기가 대화·게임 상태·행동 판단을 연결

사용자가 확정한 지시를 받아, 현재 가능한 행동을 판단하고 실행기에 전달합니다.

실행 뒤에는 Unreal이 확인한 진행·완료·실패를 조정기가 다시 받습니다.

약 1분. 사용자가 제공한 4개 역할의 시퀀스 다이어그램을 기준으로 설명합니다. 순서 재생 버튼을 누르면 각 메시지를 강조합니다. 대화 AI의 행동 요청 후보는 현재 구현에서 사용자가 확정한 뒤 조정기로 들어옵니다. 게임 필터는 관측 가능한 사실과 행동 후보를 주며 대화는 넣지 않습니다. 조정기가 대화와 관련 기억을 합쳐 행동 AI에 전달합니다. 행동 AI가 고른 제안은 조정기의 응답 검사와 최신 상태 재검사를 거쳐 실행 명령으로 바뀝니다. 실제 엔진 결과가 돌아와야 진행 상태를 갱신합니다.

원본: 사용자 첨부 설계 이미지(2026-10-02). 구현 근거: 조정기 통합 안내. 저장소 접근 권한이 필요할 수 있습니다.

AI가 “도착했다”고 말한 것과
게임에서 확인한 도착을 구분합니다.

약 50초. 입력을 조합하는 것뿐 아니라 정보의 출처와 시점을 유지하는 것이 핵심입니다. AI의 말은 대화이고 위치나 발판 상태는 게임 관측입니다. 모델은 관측에서 제공한 후보 중 하나를 선택합니다. 선택 응답의 요청 ID와 후보를 검사하고 새로 관측한 뒤 실행합니다. 행동 전제의 변경은 guard로, 실제 엔진 쪽 검사는 CanExecuteGameAction으로 확인합니다. 현재 실제 게임 바인딩 전의 기본값은 false입니다.

관련 기억은 현재 코드의 제한된 메모리 관리 범위입니다. 장기 기억 DB나 별도 기억 요약 AI를 구현했다는 의미가 아닙니다. 설명용 발판 요청은 모의 시나리오입니다. 출처: 조정기 구현 안내.

03 / 실행 결과를 관리하는 이유

발판에 도착해도, 요청은 아직 진행 중

“내가 통과할 때까지 밟고 있어.” → 통과할 때까지 유지했는지를 확인해야 완료입니다.

협동 퍼즐 예시설명용 모의 시연

Unreal → 조정기 상태 보고

  1. 접수accepted
  2. 이동 중moving
  3. 발판 유지holding
  4. 플레이어 통과 대기waiting_for_player
  5. 통과까지 유지 확인completed

완료 조건
플레이어 통과 + 통과까지 발판 유지

접수

약 1분. 기존 CoopAIFlow의 단계 재생과 격자 퍼즐 표현을 재사용했습니다. 이것은 구현된 상태 규칙을 설명하는 모의 애니메이션이며 실제 Unreal이나 모델을 호출하지 않습니다. 플레이어 발판의 구체적인 작동·유지 규칙은 실제 맵을 연결할 때 맞춥니다. 장면은 AI 발판의 유지와 플레이어 통과를 강조한 예시입니다.

시연 재생을 눌러 접수, 이동, 발판 유지, 통과 대기, 완료를 보여 줍니다. moving/holding/waiting_for_player는 status=running의 phase입니다. holding과 waiting에서는 plate_held=true가, 완료에서는 player_passed=true와 held_until_passage=true가 실제 결과로 확인되어야 합니다. 도착만으로 완료 처리하지 않습니다. PDF에는 통과 대기 장면과 전체 상태 목록을 담습니다.

04 / 이번 주 구현 · 연결 규격

각자 만든 기능은 JSON 5종으로 연결

게임·모델의 내부 구현이 바뀌어도, 양끝의 변환 코드를 바꿔 연결할 수 있도록 설계했습니다.

데이터누가 누구에게전달하는 내용
01게임 관측observation경민의 게임 필터 → 영호현재 보이는 객체·상태·실행 가능한 행동
02판단 입력decision_input영호 → 준영의 행동 AI사용자 지시·대화·기억·최신 관측
03판단 응답decision_response준영의 행동 AI → 영호허용된 후보에서 고른 행동 / 되물을 질문
04실행 명령execution_command영호 → 준영의 Unreal 실행기검사를 통과한 행동·실행 ID·실행 조건
05실행 결과execution_event준영의 Unreal 실행기 → 영호실제 접수·이동·유지·완료·실패·정지

현재 행동 후보 move_to hold_plate wait

공통 계약 v1 구현 · 실제 팀원 규격과 대조 예정

약 1분. 이번 주 만든 연결부 5개는 JSON 데이터 계약 5종입니다. Unreal Blueprint 함수 5개와는 다른 구분입니다. 경민은 게임 관측, 준영은 판단 응답과 실제 실행 결과를 연결하면 됩니다. 저는 관측을 받아 입력을 만들고, 응답을 검사해 실행 명령을 보냅니다. 현재 행동은 이동, 발판 유지, 대기이며 팀의 실제 게임 행동 이름과 맞출 예정입니다.

모델이 공통 JSON을 바로 받으면 ACTION_MODEL_URL로 연결하고, 기존 채팅 API 등의 형태를 유지하면 decide 어댑터에서 변환합니다. 객체 ID, 좌표와 시점, 실제 접촉·통과 이벤트는 게임 쪽과 합의해야 합니다. 팀원 API 주소와 맵 경로가 없어 경계를 분리해 두었습니다. 출처: JSON Schema와 예제.

약 50초. 실제 개발한 화면의 모의 실행 검증 스크린샷입니다. 사진 속 mock 표시는 실제 팀원 게임을 연결한 화면이 아니라는 뜻입니다. 왼쪽에서 요청을 보내고 취소할 수 있으며, 위의 상태는 접수가 아니라 발판 유지 중임을 보여 줍니다. 음성 연결에서는 조각 전사나 위임 이벤트만으로 바로 실행하지 않고 사용자가 후보를 확정합니다.

요청 수정·취소 뒤 늦게 온 모델 결과는 버립니다. 실행 연결이 끊기면 실패나 완료를 임의로 만들지 않고 미확인 상태로 남겨 중복 실행을 막습니다. HTTP 취소만으로 엔진 정지를 확인하지 않습니다. 코드 기준은 10/1 main 커밋 869708e입니다. 이후 팀원 사용법 문서의 로컬 추가와는 구분합니다.

테스트 개수는 통과한 시나리오 수입니다. 실제 게임 성능이나 모델 정확도 수치가 아닙니다.

약 40초. 55개 모두가 이번 주 새 기능 테스트는 아닙니다. 기존 34개와 이번에 추가한 21개를 합친 수치입니다. Chrome을 실제로 실행했지만 게임·모델·새 음성 경로는 모의 데이터로 검증했습니다. UE 5.8.3 Editor와 Game Development 빌드, 기존 문자 출력의 ACK·연결·잠금 회귀는 9/30 실제 엔진에서 확인했습니다. 이는 새 퍼즐의 실제 이동이나 새 음성 종단 검증과 다릅니다. Shipping 패키징도 아닙니다.

팀원이 각자 구현했다고 보고한 자연어 입력·이동, 퍼즐 상태 추출은 존재하지만 이 조정기와의 실제 통합은 아직 검증하지 않았습니다. 1초 이하 응답도 측정 결과가 아니라 개선 목표 의견입니다. 출처: 9/30 검증 및 10/1 재검증 기록.

약 45초. 10월 2일 전달받은 회의 내용에서 10월 8일까지의 목표는 말로 내린 명령이 실제 움직임으로 이어지는 것입니다. 영호의 실제 데이터 연결, 준영의 행동 선택과 실제 동작 연결은 전달된 작업입니다. 경민의 다음 주 세부 업무는 비어 있어 임의로 배정하지 않았습니다.

오른쪽은 통합을 위해 제안하는 자료와 확인 순서입니다. 우선 확정 텍스트 한 건이 실제 게임에서 왕복하는지 확인하고, 실제 마이크·음성 흐름을 연결합니다. 모델 응답 시간과 캐릭터 행동 시작 시간을 분리해 측정할 것을 제안합니다. 1초 이하 목표의 측정 구간과 성능 기준은 아직 확정되지 않았습니다. 교수님께 논의할 점: 처음에는 제한된 사전 정보와 행동 후보를 제공하는 실험으로 시작하고, 이후 정보 제공 범위를 바꿔 비교할지입니다. 이는 논의안이며 확정한 실험 설계가 아닙니다.
