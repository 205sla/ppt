“내가 지나갈 때까지 발판을 밟고 있어 줘.”

설명을 위해 만든 자동 애니메이션입니다. 실제 게임·모델 실행 결과가 아닙니다.

우리의 목표는 자연어 지시를 받아 사람과 함께 과제를 끝내는 동료 AI입니다.

  1. 사람의 목표를 받는다“내가 지나갈 때까지 발판을 밟고 있어 줘.”
  2. 상황에 맞는 행동을 고른다단순 이동이 아니라 발판을 계속 유지하는 행동이 필요합니다.
  3. 실제 결과까지 확인한다문이 열린 뒤 사람이 통과한 것을 확인해야 과제가 끝납니다.
게임을 실험 환경으로 쓰는 이유

상태·행동·성공 조건을 정하고, 같은 상황을 반복할 수 있습니다. 지시 변경이나 경로 차단도 통제해 넣을 수 있습니다.

자동 시연은 발판 유지와 사람 통과 사이의 시간 의존성을 보여 준다. 도착 이벤트를 과제 성공과 혼동하지 않는다. 실제 게임 판정은 엔진 이벤트로 구현할 계획이다.

검증 질문

같은 기반 모델에서, 재판단 방식과 과제에 맞춘 학습은 협동 성능·반응 시간·호출량에 각각 어떤 영향을 주는가?

조정기·기억·실행기는 일반 코드입니다. 파인튜닝은 기존 행동 AI의 가중치를 바꾸며 AI를 하나 더 추가하지 않습니다.

확정한 주제에 파인튜닝을 포함하되 두 효과를 한꺼번에 주장하지 않는다. 호출 시점과 행동 선택을 각각 분리해 검증한다.

지시를 확정한다

음성 인식 중간 결과나 침묵을 실행 동의로 처리하지 않습니다. 확정된 요청을 사용합니다.

실제 상태로 검사한다

오래된 요청·중복 실행·허용되지 않은 행동을 코드가 검사합니다.

실제 결과를 받는다

명령 접수와 과제 성공을 구분합니다. 실행 결과가 불명확하면 먼저 상태를 확인합니다.

기억은 관련 대화·확인된 결과를 보관하는 코드입니다. 실시간 상태를 파인튜닝 가중치로 대신하지 않습니다.

파인튜닝 모델을 별도 세 번째 AI로 그리지 않는다. 대화 AI에서 확정한 요청을 조정기가 전달하고 실행 결과가 돌아오는 폐회로가 목표다.

상황이 유지되는 구간과 중요한 변화가 생기는 구간을 구분합니다.

호출 위치를 설명하는 모형입니다. 실제 호출 절감률이나 성능 결과가 아닙니다.

호출을 검토할 사건

  • 새 지시 확정사용자가 목표나 대상을 바꿈
  • 선행 조건 변화목표 행동에 필요한 길·객체 상태가 바뀜
  • 확인된 실행 실패엔진이 실패를 보고해 다음 선택이 필요함

정상 이동 중의 작은 좌표 변화는 호출 조건에서 제외합니다. 반복 사건을 합치고 호출 상한을 둡니다.

두 방식의 공통 조건

실행 검사·취소 확인·다음 하위 행동 처리·관측 주기는 같게 두고, 호출 시점만 비교합니다.

그림은 호출 정책의 차이를 설명하는 임의 시간선이다. 고정 주기도 여러 간격으로 비교해야 느린 기준을 일부러 골랐다는 문제가 없다.

아닙니다. 판단 정확도와 재호출이 개선될 가능성을 측정합니다. 모델 크기나 출력 길이를 바꾼 효과는 별도로 봅니다.

정답 관계를 외우는 것 아닌가요?

맵·관계·플레이 단위로 데이터를 나누고, 새로운 관계 조합에서 평가합니다.

이미 있는 연구를 반복하는 것 아닌가요?

알려진 구조와 학습법을 출발점으로 삼아, 명세한 협동 조건에서 두 개선의 효과와 비용을 분리해 검증합니다. 기법 자체의 신규성은 추가 검토 대상입니다.

이번 학기 범위는 어디까지인가요?

기존 퍼즐과 행동 목록에서 시작합니다. 영상 인식·임의 코드 이해·온라인 학습은 핵심 실험에 동시에 넣지 않습니다.

최종 산출물을 구체적으로 설명한다. 코드 연결만으로 기여를 주장하지 않고 비교 조건과 검증 가능한 결과를 함께 남긴다.
