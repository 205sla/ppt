대화 AI와 행동 AI를 코드로 연결한다

동작 설명용 예시 · AI 역할은 두 개

        

        

        
대화 AI는 GPT-Live 음성 세션, 행동 AI는 별도 LLM 하나입니다. 행동 선택·복잡한 계획·재판단은 모두 같은 행동 AI의 작업입니다. 조정기는 전사와 상태를 결합하고 출력 형식·작업 버전·전제조건을 검사하는 일반 코드이며 세 번째 AI가 아닙니다. 언리얼은 검증된 명령으로 이동과 장치를 실행합니다.
client delegation을 통해 앱이 한 행동 백엔드에 요청을 보냅니다. 로컬·원격 모델은 이 자리를 교체하는 비교 후보이고 여러 행동 모델을 동시에 사용하지 않습니다. 게임 JSON은 행동 AI에, 확인된 결과와 짧은 문맥은 대화 AI에 전달합니다. 출처: WebRTC, client delegation. 두 AI로 제한하는 설계 결정은 2026-09-19 사용자 요청입니다.

03 · 입력과 결과의 구분
게임 JSON과 Live 문맥은 전달 형식이 다르다

        

        

        
전사 delta에는 확정된 발화 종료 이벤트가 없음 · 전사 조각만으로 행동 실행을 확정하지 않음

        
client delegation의 session.delegation.created는 ID·target·offset 같은 메타데이터입니다. 사용자 지시문을 포함하지 않으므로 우리 앱이 전사와 작업 상태를 결합합니다. session.input은 세션 시작 시 과거 텍스트 대화를 주는 필드입니다. 실행 중 문맥은 append 이벤트로 보냅니다. thinking/commentary/instructions append의 content는 최대 500토큰의 문자열이며 delegation_id가 필수입니다. 작업 결과는 실제 받은 위임 ID를 유지하고 일반 문맥은 null을 씁니다. appends ACK는 음성 재생·행동 성공을 증명하지 않습니다. instructions.append는 앱 지침용이며 게임 관찰을 지침으로 승격하지 않습니다. Live 문맥·전사 · 공식 위임·결과 이벤트

      


      

        
04 · 게임 상태 추상화
AI가 아는 정보만 골라 전달한다

        
3D 공간의 격자 표현 · 전체 상태는 디버깅·채점용
플레이어의 설명은 출처와 확인 여부를 함께 저장한다.

        
보이지 않는 레버의 존재와 정답을 자동으로 알려주지 않는다.

        
전체 상태 보기로 바꿔도 오른쪽 AI 입력은 제한된 관찰을 유지합니다. 전역 상태는 채점에만 쓰고 AI 판단으로 새지 않아야 합니다. 알려진 공간은 기억에 저장하고 바뀐 관련 정보 위주로 전송합니다. 후보 행동 목록에서도 비공개 객체가 드러나지 않게 합니다. 발판과 문 사이의 관계를 사람이 말해줬다면 미확인 발언으로 저장합니다. 이 지도는 설명용 모식도이며 실제 언리얼 화면이 아닙니다.

프로그램은 가능한 행동을 정의하고, 모델은 상황에 맞는 선택을 한다.

        
행동 AI는 실험별로 LLM 하나를 사용합니다. 로컬 Gemma와 원격 모델은 교체 비교 후보이며 실제 지연·출력 안정성은 미측정입니다. 질문이 필요하면 행동 AI가 질문 내용을 반환하고 대화 AI가 음성으로 전달합니다. JSON Schema로 형식과 enum을 제한하되 문법 성공과 올바른 선택은 따로 평가합니다. action_id를 엔진 함수에 매핑하며 모델이 임의의 코드를 실행하지 않습니다. 모호한 지시에서는 두 발판 중 임의로 정하지 않고 질문합니다. LM Studio Structured Output

      


      

        
06 · 언리얼 행동 실행기
한 번 받은 행동을 여러 프레임에 걸쳐 수행한다

        
이동과 접촉 판정은 엔진이 수행
Accepted→Moving→Holding

        

        
조정기는 작업 버전·행동 ID·전제조건을 검사한 뒤 실행기를 호출합니다. 작업 ID는 서버가 부여하며 중복 실행을 막습니다. Accepted는 접수이고 Holding은 유지 중이므로 아직 작업 완료가 아닙니다. AI가 직접 못 보는 통과 여부는 플레이어 확인을 기다립니다. 마지막 음성은 실제 접촉 결과를 받은 후에만 전달합니다. LLM 호출 없이도 엔진의 이동·유지는 계속됩니다. 이동 실패와 취소는 별도 상태로 관리합니다.

대화 AI는 소통, 행동 AI는 판단, 엔진은 실제 동작을 맡는다.

        
현재 행동이 유효할 때만 유지 · 행동 AI의 중복 요청은 조정기에서 정리 · 별도 계획 AI 없음

        

        
앞서 시작한 발판 유지가 아직 유효하고 사람이 역할 교대를 요청한 상황입니다. 대화 AI가 요청을 듣고 같은 행동 AI가 다음 계획을 판단합니다. 이 사이 엔진은 기존 발판 유지를 수행합니다. 행동 AI가 두 개이거나 빠른 모델과 느린 모델을 동시에 실행하는 그림이 아닙니다. 제안 전달은 판단 결과를 설명하는 것이며 실행 완료를 주장하지 않습니다.
행동 AI 요청은 한 번에 하나를 기본으로 관리하고, 새 지시는 최신 작업으로 갱신해 오래된 응답을 폐기합니다. 유지 조건이 깨지거나 취소가 오면 일반 코드가 중단·대기로 전환합니다. 막대 길이는 개념 설명이며 실제 지연은 측정해야 합니다.
